# Alternatives for unpaired RNA–H3K27ac–H3K4me3 integration

**Recommendation:** make a small, isolated pilot of **scConfluence’s count-autoencoder plus regularized inverse optimal transport architecture**, with the implementation prerequisite below. It most directly separates retention of assay-specific features from cross-assay alignment. **UINMF is the simpler CPU-capable comparison.** These are prospective candidates, not demonstrated improvements on this project.

This is a focused narrative review, searched 2026-10-31 America/New_York (2026-11-01 UTC). Only existing counts and permitted gene/region annotations are proposed as fitting inputs. No paired-cell bridge, transferred validation labels, protein measurements, new atlas, or new dataset is required or proposed. No training, installation, scientific metric recomputation, or production-file edit was performed.

## Implementation finding that changes the recommendation

The inspected scConfluence default-branch head is **`14d81e2ca679e161ec5c6806103a66c14fcdcd9a`**. In [`model.py`, lines 400–429](https://github.com/cantinilab/scconfluence/blob/14d81e2ca679e161ec5c6806103a66c14fcdcd9a/scconfluence/model.py#L400), each loop iteration assigns the current pair’s IOT and Sinkhorn losses to the same accumulator names, then doubles each variable. The final dictionary therefore contains twice the **last nonempty pair’s** losses rather than a sum across all pairs. This is a static source finding; it was not tested through training. It prevents treating an unmodified three-assay call as the advertised joint alignment objective. A single-pair call also has a factor-of-two weighting difference.

Consequently, the recommendation is conditional on a small reviewed correction with a check that every declared pair contributes and changing pair order does not drop terms. No correction was made here. Running two unrelated pairwise models is not an equivalent workaround: their RNA coordinates need not share one gauge. If unchanged released code is essential, prefer the UINMF comparison first.

Other inspected heads were uniPort `c2743c5451765d5278a867ac051abda5c4d75189`, LIGER `afecff11de78c3089b1961017d57fe855794556c`, and Pamona `44322c487eb907cf021d5ee7bd1a3ff3f124c14b`. These are research snapshots, not installed or endorsed production pins.

## A bounded, testable first alternative

For a future scConfluence pilot, keep the existing worlds, cell pools and annotations. Preserve integer counts in a separate reconstruction layer. Feed each encoder all training-QC-eligible features after per-cell normalization/log transformation, using `rep_in=None`, `rep_out="counts"`, and a fixed count likelihood. NB for all three assays is a reasonable first modelling assumption supported by the API; it has **not** been validated for these histone counts. Use one predeclared latent dimension, rather than starting another large hyperparameter grid. Published/default settings are starting values, not evidence of suitability.

Construct weak alignment costs from existing gene/region links for the three assay pairs, while retaining original region features in the mark encoders. Define the feature universe, link weights, normalization and any cost scaling from training counts and permitted annotations only. Do not choose them using hidden state, same-cell pairing, assessment outcomes, or labels later claimed as independent validation. Active-mark gene scores are proxies; distance-to-gene links are not experimentally established regulation.

Avoid copying the paper’s runtime estimate into a project budget: its encoder used PCs. The inspected data loader keeps sparse matrices until minibatches, but encoder/decoder layers and minibatches are dense. Full cross-cost storage is also material: three float64 matrices for 2,000 cells per assay occupy about **96 MB**; at 10,000 each, **2.4 GB**, before copies and model memory. These are arithmetic storage estimates, not measured resource use. Compute feature-dependent parameter/input sizes before committing to a full-cohort run; no resources or active fits were inspected here.

Use a new follow-up directory and an explicit protocol revision, preserving the completed 32-fit study. Reuse its complementary endpoints: absolute state costs and normalized state-transport gap on comparable public pools; fixed source-standardized cross-assay decoder transfer; within-assay preservation and preassignment hubness/coverage. Report all assay directions and failures. A partial method must also report transported mass and unmatched populations: a low cost achieved by discarding cells is not directly comparable with the full no-reuse assignment oracle. Forced full-pool matching can remain a common coordinate diagnostic, with the native partial coupling reported separately.

## What a positive result would establish

Direct feature input avoids irreversible truncation **before** learning; it does not remove the learned bottleneck, depth effects, nuisance factors, or all preferences for high-signal features. Better count reconstruction or a smaller training OT loss is not independent alignment validation. Guide-derived agreement is partly self-trained; modalities can mix while biologically different states align.

The attainable conclusion is improved recovery/preservation of specified cross-assay **state** relationships under the tested inputs and assumptions. It does not recover the unobserved same-cell residual joint distribution, certify conditional independences, or establish causal edges. Reconstructed means, factor loadings, transport plans and annotation links must not be relabelled as causal observations.
